## 개요

메인 대화의 턴이 답으로 끝나면 작은 모델(`haiku`)에 한 번 물어, 사용자가 바로 다음에 보낼 만한 요청을 최대 3개 받는다. 받은 요청은 입력창 위에 한 줄에 하나씩 보여 주고, 사용자는 `$1`을 입력하거나 클릭해서 그 문구를 쓴다.

같은 말을 매번 직접 치지 않고 다음 단계로 넘어가게 하려는 모드다. 제안은 덤이라서 모델 호출이 실패하거나 쓸 만한 제안이 없으면 아무것도 띄우지 않는다.

하지 않는 것은 다음과 같다.

- 서브에이전트의 턴, 사용자가 중단한 턴, 거절이나 API 오류로 끝난 턴에는 제안을 만들지 않는다.
- 제안을 저장하거나 다시 꺼내 보는 기능은 없다. 닫은 제안은 되살릴 수 없다.
- 모델 호출만 끄는 설정은 없다.

이 모드는 [hamzafer/claude-code-mods](https://hamzafer.github.io/claude-code-mods/mods/next-steps/)의 next-steps에서 아이디어를 얻었다. 원본 코드는 보지 않고 동작 설명만 참고해 새로 구현했다.

## 빠른 시작

마켓플레이스를 등록한 적이 없다면 먼저 `/plugin marketplace add oobg/claude-code-mods`를 실행한다. 그다음 모드를 설치한다.

```
/plugin install next-prompts@oobg
```

설치한 모드는 Claude Code를 다시 시작하거나 `/reload-plugins`를 실행하면 적용된다. 설치 직후에는 아무것도 보이지 않고, 첫 턴이 끝난 뒤에 제안이 나타난다.

1. 평소처럼 요청을 보내고 Claude의 답을 기다린다.
2. 답이 끝나면 입력창 위에 `다음 제안` 제목과 함께 `$1:`, `$2:`처럼 번호가 붙은 문구가 나타난다.
3. 문구를 클릭하면 바로 보내고, 입력창에 `$1`을 치면 그 자리에 1번 문구가 들어간다.

## 사용법

### 제안이 나타나는 조건

턴이 끝날 때 아래 조건을 모두 채우면 제안을 만든다.

- 메인 대화의 턴이다. 서브에이전트의 턴(`agentId`가 있음)은 건너뛴다.
- 턴이 답으로 끝났다(`reason`이 `answer`). 사용자가 중단한 턴(`isAborted`), 거절(`refusal`), API 오류(`error`)로 끝난 턴은 제외한다.
- 답 본문이 120자 이상이다(`MIN_ANSWER_CHARS`). 답 본문은 그 턴에 Claude가 마지막으로 보여 준 글이다. 생각만 하고 글을 남기지 않은 턴은 본문이 비어 있으므로 제외된다.

모델에는 2~3개를 요청하지만, 60자를 넘거나 겹치는 줄은 버리므로 1개만 남을 수도 있다.

### 제안 고르기

- 입력창에 `$1`을 치면 `$1`이 1번 문구로 바뀐다. 글 중간에서도 쓸 수 있다.
- 번호(`$1:`)를 클릭하면 입력창의 글을 1번 문구로 바꾸고 제안을 닫는다. 보내지는 않는다.
- 문구를 클릭하면 그 문구를 사용자 말로 바로 보낸다. 입력창에 쓰던 글은 함께 보내지 않는다.

```
다음 제안  닫기
  $1: 바뀐 내용을 README 문서에 반영해줘
  $2: 커밋해줘
```

### 제안 닫기와 숨김

- `닫기`를 클릭하면 제안을 닫는다. 닫은 제안은 다시 열 수 없고, 다음 턴이 위 조건을 채우고 끝나면 새 제안이 나타난다.
- Claude가 작업하는 동안에는 제안을 숨긴다.
- 새 프롬프트를 보내면(슬래시 명령 포함) 제안을 지운다.

### 나타나는 모양

제안은 한 줄씩 차례로 나타난다(0.7.0부터).

- 줄은 120ms 간격으로 하나씩 시작하고, 한 줄은 약 320ms에 걸쳐 앞에서부터 글자가 채워진다. 화면은 40ms마다 갱신한다.
- 글자가 채워지는 동안에는 흐린 색으로 보이고, 다 나오면 보통 색으로 바뀐다.
- `다음 제안` 제목 줄과 `닫기`는 첫 줄과 함께 나타난다. 아직 나오지 않은 줄은 빈 줄로 자리를 잡아 두어 입력창 위 영역의 높이가 흔들리지 않는다.
- 애니메이션 도중에도 `$1`을 입력하거나 번호나 문구를 클릭하면 화면에 보이는 일부가 아니라 전체 문구를 넣거나 보낸다.
- 애니메이션 도중 `닫기`를 클릭하거나 새 프롬프트를 보내면 그 자리에서 멈춘다. 모드 코드를 다시 불러와도(핫 리로드) 제안은 남고, 남은 애니메이션 없이 전체 문구로 보인다.

### quick-replies와 함께 쓰기

quick-replies를 함께 설치하면 두 모드가 입력창 위 영역을 나눠 쓴다. 다음 제안이 위에, 프리셋이 아래에 놓이고, 번호는 하나로 이어진다. 다음 제안은 늘 `$1`부터 시작하고, 프리셋은 떠 있는 제안 개수 다음 번호부터 매긴다. 제안이 2개면 프리셋은 `$3`부터다.

quick-replies의 접기(`$0`)는 프리셋에만 적용된다. 다음 제안은 접히지 않고 늘 전체 문구로 보인다.

## 키와 명령

| 입력 | 동작 | 조건 |
| --- | --- | --- |
| `$1`~`$3` 입력 | `$`와 숫자를 그 번호의 제안 문구로 바꾼다 | `$`가 글 맨 앞이거나 바로 앞이 공백일 때. 그 번호의 제안이 떠 있을 때. 선택 영역 없이 한 글자를 친 경우만 |
| 번호(`$n:`) 클릭 | 입력창의 글을 그 문구로 바꾸고 제안을 닫는다 | 제안이 보일 때 |
| 문구 클릭 | 제안을 닫고 그 문구를 사용자 말로 바로 보낸다 | 제안이 보일 때 |
| `닫기` 클릭 | 제안을 지우고 애니메이션을 멈춘다 | 제안이 보일 때 |
| 슬래시 명령 | 해당 없음 | 이 모드는 명령을 등록하지 않는다 |

`$1`로 바꾼 내용은 Claude Code의 되돌리기 키 `ctrl+_`로 되돌린다.

## 화면 구성

| 요소 | 내용 | 표시 조건 |
| --- | --- | --- |
| 제목 줄 | 흐린 색 `다음 제안` | 첫 제안의 글자가 하나라도 보일 때. 그 전에는 빈 줄 |
| `닫기` | 흐린 색 버튼. 제목 줄 오른쪽 | 제목 줄과 함께 |
| 번호 | `$1:` 형식. 테마 색 `suggestion`(Claude Code가 입력창의 `/명령`에 쓰는 색) | 제안 줄마다. 9번까지만 붙는다(`MAX_NUMBER`) |
| 제안 문구 | 두 칸 들여 쓴 한 줄. 채워지는 동안은 흐린 색, 다 나오면 보통 색 | 그 줄의 차례가 오면. 그 전에는 빈 줄 |
| 영역 전체 | 위에 한 칸을 띄운 다음 제안 블록 | 제안이 있고 Claude가 작업 중이 아닐 때 |

설문이 떠 있을 때(`hasSurvey`)와 터미널, 데스크톱이 아닌 화면에서는 이 모드가 입력창 위 영역에 손대지 않는다.

## 동작 방식

### 이벤트

| 이벤트 | 하는 일 | 소스 |
| --- | --- | --- |
| `session.start` | `reveal`을 비운다. 핫 리로드로 끊긴 애니메이션 대신 제안 전체를 보이게 한다 | `hooks/register.tsx`: `register` |
| `prompt.submit` | `generation`을 1 올리고 `suggestions`와 `reveal`을 비운 뒤, 보낸 글을 `lastPrompt`에 남긴다. 슬래시 명령도 포함한다 | `hooks/register.tsx`: `register` |
| `prompt.edit` | 방금 친 글자가 `$1`~`$9`를 이루면(`typedNumber`) 그 번호의 제안으로 `$`까지 덮어 바꾼다. 그 번호의 제안이 없으면 그대로 둔다 | `hooks/register.tsx`: `register`, `hooks/band.ts`: `typedNumber` |
| `turn.complete` | 엔진의 처리(`next(e)`)를 먼저 끝낸 뒤, 조건을 채우면 `suggest`를 기다리지 않고 시작한다. 턴 마무리를 붙잡지 않으려는 것이다 | `hooks/register.tsx`: `register`, `suggest` |
| `ui.render` (`AbovePrompt`) | 다른 모드가 그린 틀(`next(e)`)에 자기 줄을 끼워 넣는다. 작업 중이거나 제안이 없으면 자기 줄을 뺀다 | `hooks/register.tsx`: `register`, `hooks/band.ts`: `withBandSection` |

`turn.complete`의 조건은 `e.agentId === undefined && e.reason === 'answer' && !e.isAborted && e.answer.length >= MIN_ANSWER_CHARS`이다.

### 제안 만들기

1. `buildPrompt`가 `lastPrompt`의 끝 1000자와 답 본문의 끝 4000자(`MAX_CONTEXT_CHARS`)로 요청을 만든다. 잘린 쪽 앞에는 `…`를 붙인다.
2. `$.model.complete`로 `haiku`를 호출한다(`SYSTEM` 시스템 프롬프트, `maxTokens: 200`, `effort: 'low'`, `timeoutMs: 20_000`).
3. 답이 없거나(`isAnswered`가 false) 그사이 `generation`이 바뀌었으면 버린다.
4. `parseSuggestions`가 답을 줄 단위로 나눠, 앞의 번호(`1.`, `1)`)나 글머리표(`-`, `*`, `•`)와 양끝 따옴표를 걷어 낸다. 빈 줄, 60자(`MAX_SUGGESTION_CHARS`)를 넘는 줄, 이미 나온 줄은 버리고 3개(`MAX_SUGGESTIONS`)까지 고른다.
5. 하나도 남지 않으면 아무것도 띄우지 않는다. 남으면 `animate`로 넘긴다.
6. 호출 중 예외가 나면 조용히 버린다.

`SYSTEM`은 2개 또는 3개를, 번호나 기호 없이 한 줄에 하나씩, 사용자의 언어와 말투로, 60자 이내로 고르라고 지시한다. 이미 끝낸 일이나 사용자가 거절한 일은 빼고, 고를 게 없으면 아무것도 쓰지 말라고 한다.

### 애니메이션

`animate`는 `reveal`에 첫 프레임 값을 넣은 다음 `suggestions`에 전체 문구를 넣고, `$.clock.sleep(FRAME_MS)`마다 `reveal`만 늘린다. 모든 줄이 다 나오면 `reveal`을 빈 배열로 되돌린다.

| 상수 | 값 | 뜻 |
| --- | --- | --- |
| `FRAME_MS` | `40` | 상태를 바꾸는 간격(ms). 코드 주석은 엔진이 입력창 위 영역을 초당 30번까지 다시 그리므로 33ms 이상으로 둔다고 적는다 |
| `LINE_GAP_MS` | `120` | 다음 줄이 시작하는 간격(ms). 프레임으로는 `LINE_GAP_FRAMES` = 3 |
| `LINE_MS` | `320` | 한 줄을 채우는 시간(ms). 프레임으로는 `LINE_FRAMES` = 8 |

`f`번째 프레임에서 `i`번째 줄이 보여 주는 글자 수는 `min(길이, (f - 3i + 1) × ceil(길이 / 8))`이다(`revealAt`). 글자 수는 `Array.from`으로 세므로 한글과 이모지도 한 글자로 센다.

### 취소(`generation`)

모듈 안의 숫자 `generation`이 지금 유효한 제안 회차를 나타낸다. `prompt.submit`, `닫기`, 문구 클릭 때 1씩 올린다.

- `turn.complete`는 그 시점의 `generation`을 `suggest`에 넘긴다. 모델 답이 돌아왔을 때 값이 달라졌으면 결과를 버린다.
- `animate`는 프레임마다 값을 비교하고, 달라졌으면 그 자리에서 멈춘다. 제안을 비우는 일은 `generation`을 올린 쪽이 한다.
- 모델 호출 자체를 끊지는 않는다(`AbortSignal`을 쓰지 않는다). 호출은 끝까지 가고 결과만 버린다.

### 상태

모두 `$.state`의 `next-prompts` 아래 키다. 세션 동안 유지되고 핫 리로드 뒤에도 남는다. 디스크에는 쓰지 않는다.

| 키 | 타입 | 내용 | 비우는 때 |
| --- | --- | --- | --- |
| `suggestions` | `readonly string[]` | 지금 띄운 제안. 늘 전체 문구다 | `prompt.submit`, `닫기`, 번호나 문구 클릭 |
| `reveal` | `readonly number[]` | 줄마다 지금 보이는 글자 수. 빈 배열이면 전부 보인다 | `session.start`, `prompt.submit`, `닫기`, 애니메이션 끝 |
| `lastPrompt` | `string` | 마지막으로 보낸 요청. 다음 제안의 재료 | 비우지 않고 덮어쓴다(`prompt.submit`, 문구 클릭) |

`ui.render`는 `reveal`의 길이가 `suggestions`와 다르면 애니메이션이 없는 것으로 보고 전체 문구를 그린다. `ui.render` 안에서 읽은 상태가 바뀌면 엔진이 영역을 다시 그린다.

### 다른 모드와 주고받는 것

- 입력창 위 영역은 한 트리만 그려지므로 quick-replies와 같은 틀을 쓴다. 틀은 키 `oobg-band`인 세로 `Box`이고, 각 모드는 `oobg-band:<순서>:<이름>` 키의 줄을 끼워 넣는다. 이 모드의 줄은 `oobg-band:10:next-prompts`(`ORDER` = 10), quick-replies는 순서 20이라 그 아래에 온다.
- quick-replies가 편집 화면처럼 영역을 혼자 쓸 때는 키 `oobg-band-exclusive` 틀을 돌려준다. 이 모드는 그 틀을 보면 자기 줄을 넣지 않고 그대로 넘긴다.
- quick-replies는 `{ plugin: 'next-prompts', key: 'suggestions' }`를 읽어 문자열 항목 개수를 세고, 프리셋 번호를 그다음부터 매긴다. next-prompts가 없으면 0으로 본다. next-prompts는 quick-replies의 상태를 읽지 않는다.
- 각 모드가 번호를 스스로 매기므로 틀을 합치는 순서와 상관없이 번호가 이어진다.

## 설정과 저장 데이터

설정할 수 있는 값은 없다. 제안 수, 길이 한도, 모델, 애니메이션 속도는 모두 코드 상수다.

| 종류 | 키 | 비고 |
| --- | --- | --- |
| `$.state` | `suggestions`, `reveal`, `lastPrompt` | 세션 동안만 유지. [상태](#상태) 참고 |
| `$.store` | 없음 | |
| 파일 | 없음 | |

모델 호출을 멈추려면 모드를 끄거나 지운다(`/plugin uninstall next-prompts@oobg`).

## 외부 호출과 사용량

| 항목 | 값 |
| --- | --- |
| 호출 | `$.model.complete`. 조건을 채운 턴마다 한 번 |
| 모델 | `haiku` |
| 보내는 내용 | `SYSTEM` 지시문, 사용자가 마지막으로 보낸 요청의 끝 1000자, 답 본문의 끝 4000자 |
| 보내지 않는 것 | 대화 기록, 도구 실행 결과, 답 본문에 들어 있지 않은 글 |
| 응답 한도 | `maxTokens: 200`, `effort: 'low'` |
| 제한 시간 | 20초(`timeoutMs: 20_000`). 넘으면 호출이 `aborted`로 끝난다 |
| 실패 시 | `api-error`, `empty-reply`, `aborted`, 예외 모두 아무것도 띄우지 않는다. 오류 메시지도 없다 |
| 하위 프로세스, 네트워크 | 없음 |

`$.model.complete`는 세션 자신의 API 클라이언트와 자격 증명으로 호출된다. 따라서 Claude Code 세션과 같은 계정으로 나가고, 호출할 때마다 그 계정의 사용량에 포함된다. 도구와 대화 기록 없이, Claude Code의 기본 식별 블록 뒤에 `SYSTEM`을 붙인 시스템 프롬프트로 보낸다.

## 제한 사항

- 제안 품질은 `haiku`가 받은 두 글(마지막 요청의 끝 1000자, 답 본문의 끝 4000자)에 달려 있다. 그 앞의 대화나 도구 결과는 모델이 보지 못한다.
- 답 본문이 120자보다 짧으면 제안하지 않는다.
- 60자를 넘는 제안은 버린다. 모델이 긴 줄만 내면 아무것도 뜨지 않는다.
- 제안을 기다리는 사이에 새 프롬프트를 보내면, 늦게 도착한 제안은 버린다. 이미 시작한 호출의 사용량은 그대로 든다.
- 문구 클릭으로 보낸 요청은 `@파일` 멘션을 펼치지 않는다. 엔진이 모드가 보낸 프롬프트를 그렇게 다루기 때문이다.
- 터미널과 데스크톱 화면에서만 그린다. 다른 화면에서는 보이지 않는다.

## 문제 해결

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 턴이 끝났는데 제안이 없다 | 답 본문이 120자 미만, 턴이 중단이나 거절이나 오류로 끝남, 모델 호출 실패 또는 20초 초과, 모델 답이 모두 60자 초과 | 다음 턴을 기다린다. 실패해도 오류는 표시하지 않는다 |
| 서브에이전트가 끝났을 때는 제안이 없다 | 서브에이전트의 턴(`agentId`가 있음)은 건너뛴다 | 메인 대화의 턴이 끝나면 나타난다 |
| 제안이 1개만 뜬다 | 겹치거나 60자를 넘는 줄을 버렸다 | 정상 동작이다 |
| 작업 중에 제안이 사라졌다 | Claude가 작업하는 동안에는 숨긴다(`isWorking`) | 작업이 끝나면 다시 보인다. 새 프롬프트를 보냈다면 지워진 것이다 |
| `$1`을 쳤는데 바뀌지 않는다 | `$` 바로 앞에 글자가 있거나, 그 번호의 제안이 없거나, 선택 영역이 있었다 | `$`를 글 맨 앞이나 공백 뒤에 친다 |
| 닫은 제안을 다시 보고 싶다 | 닫으면 `suggestions`를 비운다 | 되살릴 수 없다. 다음 턴을 기다린다 |
| 업데이트 뒤 예전 제목 붙은 제안이 남아 있다 | 0.3.0~0.4.0은 제안을 `{ title, text }`로 저장했다 | 렌더링과 `$번호` 치환에서 문자열이 아닌 항목은 걸러 내므로 보이지 않는다 |

## 변경 이력

- `0.7.1`: 서브에이전트의 턴에서는 제안을 만들지 않는다. `turn.complete`가 서브에이전트의 턴에도 지나가므로 `agentId`가 있으면 건너뛴다.
- `0.7.0`: 제안을 120ms 간격으로 한 줄씩, 흐린 색으로 흘려 쓰다가 다 나오면 보통 색으로 바꾼다. 진행 정도는 `reveal` 상태에 따로 두어 `$번호` 치환과 quick-replies 번호가 그대로 동작한다.
- 버전 변화 없음: 모드 폴더를 저장소 최상위에서 `mods/` 아래로 옮겼다.
- `0.6.0`: 빈 입력창의 숫자 키 단축키 대신 `$번호`로 문구를 넣는다. 번호 표시도 `$1:`로 바뀌고, 각 모드가 번호를 직접 매긴다.
- `0.5.0`: quick-replies의 접기 상태를 읽지 않는다. 다음 제안은 늘 전체 문구로 보이고, `제목 :: 요청` 형식 대신 요청만 받는다.
- `0.4.0`: 제안을 번호 버튼과 문구 버튼으로 나눴다. 번호는 입력창에 넣기만 하고, 문구 클릭은 바로 보낸다.
- `0.3.0`: quick-replies의 접기(`0`)에 맞춰 제안을 `제목 :: 요청` 형식으로 받고, 접으면 제목만 보였다. `닫기`는 클릭으로만 한다.
- `0.2.0`: 제안을 한 줄에 하나씩 보여 준다.
- `0.1.0`: 처음 추가. 턴이 끝나면 `haiku`로 다음 요청 2~3개를 제안하고, 숫자 1~3으로 입력창에 초안을 넣었다.
